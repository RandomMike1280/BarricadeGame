# copy() / apply_move() Speed Optimization — Iteration Log

Goal: improve wall-clock speed of `BarricadeState.copy` and
`BarricadeEnv.apply_move` while preserving MCTS correctness on the legacy
default path (no virtual_loss, no AMAF, no history).

Metrics (median of 5 reps, 20k iters each, fresh template state per rep):

* `copy()` per-call µs, on `fresh`/`mid`/`late`/`heavy` representative states.
* `apply_move()` per-call µs (rotating over the state's legal moves).
* `apply_action(validate=False)` per-call µs (rotating; matches mcts.py path).

Secondary check: 20-test `test_mcts` suite + pre-PR baseline regression test
(`tests/fixtures/mcts_pr_baseline.npz`) must remain bit-identical on
`visits` / `value_sum` / `virtual_visits` arrays.

Per-iteration wall-clock cross-check: `mcts_micro_bench.py` sims/sec on
16 / 32 positions, `num_simulations=400`, `batch_size=32`.

Baseline measured on this machine (Windows / Python 3.14.6 / torch 2.12.1):

| state  | copy(µs) | apply_move(µs) | apply_action(µs) |
|--------|---------:|---------------:|-----------------:|
| fresh  |   0.476  |         1.516  |           2.260  |
| mid    |   0.618  |         1.713  |           2.404  |
| late   |   0.765  |         2.008  |           2.600  |
| heavy  |   0.928  |         2.018  |           4.527  |

Microbench baseline: 1186.7 sims/sec (N=16) / 1252.9 sims/sec (N=32).
