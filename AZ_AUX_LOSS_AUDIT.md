## Double-count check

- `value_loss` and `tactical_value_loss` are the only pair that share parameters. Both losses optimize `v_θ(s)`, and gradient on the tactical batch flows back through the shared `value_head` parameters just like the real-batch gradient does — the `torch.inference_mode()` wrapper at [train.py:1733-1734](train.py) only suppresses intermediate grad-history retention on tactical tensors, it does not stop `.backward()` ([train.py:1747](train.py)) from accumulating into `value_head` parameters. The two branches target disjoint sources of error (real self-play state vs synthetic race state), the tactical branch is weighted at `0.25` ([train.py:129](train.py)), and the resulting interference acts like mild regularization rather than double-counted error. **No double-count.**
- All other heads — `lead_head`, `future_map_head`, `score_head` — are separate `nn.Module` instances ([network.py:546-552](network.py)) with no shared parameters with the value head. **No parameter sharing → no double-count risk.**
- The value head has its own post-tower (`value_tower`, [network.py:533-535](network.py), used at [network.py:570](network.py)) that feeds only the value head; policy / lead / future / score see the shared trunk output ([network.py:568-577](network.py)). Backprop on the value branch touches only `value_tower` + `value_head`; the other heads see no gradient from `value_loss`.

## Washout check

- A saturated value head (`v_θ ≈ ±1` due to `tanh`) can by definition only wash out gradients that flow *through its own parameters*. `lead_head`, `future_map_head`, `score_head` live on disjoint parameter sets ([network.py:546-552](network.py)), so they cannot be washed out by value saturation. The `tactical_value` branch's `inference_mode` wrapper ([train.py:1733](train.py)) only controls whether intermediate tensors retain grad history; it does not prevent the tactical gradient from saturating `value_head`. The synthetic targets are hard-clip `±1` ([train.py:2168](train.py)) so a saturated `v_θ` already at the target pushes the tactical MSE to 0 — the loss itself does not absorb gradient in a runaway way.
- `lead_loss_weight=0.1` ([train.py:131](train.py)) operates on a separate head with a `symlog` target transform ([train.py:2102-2104](train.py)) that keeps gradient magnitudes bounded across the full race-margin range; `lead_mask` zeros games where the env did not emit a `lead` ([train.py:1106](train.py)).
- `score_loss_weight=0.01` ([train.py:133](train.py)) is intentionally small; the mask is `0.0` for losses/draws ([train.py:2496-2507](train.py)), so the active gradient only fires on winning-side positions with smooth-L1 targets — well-conditioned.

## Verdict

**No defect found.** The four auxiliary heads (`tactical_value`, `lead`, `future`, `score`) do not double-count loss with the primary `value_loss`, and none of them can be washed out by a saturated value head because they live on disjoint parameters. No fix is applied; no commit is made.
